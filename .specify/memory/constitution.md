# Noble Portfolio OS Constitution

## Core Principles

### I. Value & Proof-of-Work First
The portfolio is designed as an interactive proof of capability, not a passive resume. The primary focus of every page, card, and interaction is to demonstrate tangible business value, ROI, and engineering excellence in AI Automations, Full-Stack Development, and Meta Growth Funnels.

### II. Single Config Source of Truth
All developer-specific assets, credentials, copy, case studies, and agent parameters must be configurable from a single centralized configuration file (`config/portfolio.config.ts`). No hardcoded personal strings should be dispersed across component logic.

### III. Autonomous Assistant Integration
The website functions as a 24/7 autonomous operations assistant. The embedded AI agent must be capable of answering visitor inquiries, collecting structured client briefs, generating executive summaries, and dispatching webhook notifications to external communication channels.

### IV. Performance & Fluid Aesthetics (Codium Baseline)
The user interface must strictly conform to modern high-end dark aesthetics:
- Obsidian & Deep Zinc background `#08090b` with radial ambient mesh.
- Bento Grid layout with 1px translucent borders and glassmorphism.
- 100/100 Core Web Vitals performance on desktop and mobile.

### V. Defensive Resilience & Safe Fallbacks
All external API connections (AI inference, Webhooks) must implement graceful local fallbacks. If an API key is missing or an endpoint fails, the portfolio must continue to function seamlessly without breaking UI or throwing unhandled exceptions.

## Governance
This constitution governs all future spec planning, task breakdowns, and implementations for the Noble Portfolio OS project.
